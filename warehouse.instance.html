warehouse.instance.bin_type module¶

A class for identifying a bin type.

Each bin in our warehouse has a type. Usually, there are some part-specific bins. Additionally, there are small and large random bins that can house different types of part. Each bin type has an associated amount of bins (of that type). The amount must be a positive integer number.

...     b2 = BinType(1, "cupboard", 7, False)
...     b3 = BinType(None, "wardrobe", 33, True)
...     b4 = BinType(None, "drawer", 34, True)
...     b5 = BinType(4, "shed", 77, False)

warehouse.instance.element module¶

A class for identifying an element of our simulations.

Element objects are the basis for our model. They are the base classes for bin types and parts as well as events. All elements, i.e., subclasses of this class, such as instances of Event, BinType, and Part, are immutable and hashable, too.

Note regarding the comparison functions: <, <=, >, and >= only use the key attribute. The same holds for the hash code returned by hash(). This if for performance reasons, as sorting and priority-queueing usually only use < comparisons and each element with a different key must also have a different name anyway.

However, == and != also use the name attribute. This may be useful for comparing data across instances.

>>> with context():
...     e1 = Element(0, "A")
...     e2 = Element(None, "B")
...     e3 = Element(2, "C")
...     e4 = Element(None, "D")

>>> str(e1)
'Element0'
>>> str(e2)
'Element1'
>>> str(e3)
'Element2'
>>> str(e4)
'Element3'

>>> repr(e1)
"Element(key=0, name='A')"
>>> repr(e2)
"Element(key=1, name='B')"
>>> repr(e3)
"Element(key=2, name='C')"
>>> repr(e4)
"Element(key=3, name='D')"

>>> csv1 = list(Element.to_csv((e1, e2, e3, e4)))
>>> for txt in csv1[:-3]:
...     print(txt)
key;name
0;A
1;B
2;C
3;D
# key: the unique key of the element within its type
# name: the unique name of the element (unique over all elements of all types)

>>> for elem in Element.from_csv(csv1):
...     print(repr(elem))
Element(key=0, name='A')
Element(key=1, name='B')
Element(key=2, name='C')
Element(key=3, name='D')

warehouse.instance.event module¶

Events provide information about things that happen in a simulation.

They both drive the simulation and are its output. They are a part of a simulation scenario (instance). In this function, they tell the simulation what outside events happen, e.g., that some parts have arrived and should be stored in the warehouse. As the output of the run method of the Simulation class, they tell us what happened and when it happened. The concrete event classes are implemented in package event.

Note regarding the comparison functions: <, <=, >, and >= only use the time attribute. This if for performance and consistency reasons. Inside the simulation, events enter a priority queue. There, only the original sequence of events as well as their time stamps should matter. Sorting and priority-queueing usually only use < comparisons and each element with a different key must also have a different name anyway.

However, == and != may also use other attributes. This may be useful for comparing data across instances.

warehouse.instance.time module¶

Time utilities.

In our simulation, the time is represented as integer values int representing dates and times in millisecond resolution, i.e., a time unit of 1 corresponds to one millisecond. However, we store and retrieve times as ISO timestamps, where we clamp off zero components that are not used. Furthermore, as time zone, we by default use Asia/Shanghai time. This means that a date/time without UTC offset, i.e., without something like “+08:00” or “-10:00”, is treated as Shanghai time. Of course, you still provide time stamps in UTC time by using suffix “+00:00”.
